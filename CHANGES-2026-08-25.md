## Commit `1565f15` — Phase 17: Plugin updates

### What changed

#### New files added

| File | Purpose |
|---|---|
| `minecraft-plugin/src/main/java/com/umbrellaos/plugin/VerificationCommand.java` | Implements `/verify <code>`, `/umbrella status\|help`, and `/appeal` commands. | `minecraft-plugin/src/main/java/com/umbrellaos/plugin/MaintenanceEnforcer.java` | Listens to `AsyncPlayerPreLoginEvent` (fires before the player fully joins). If maintenance mode is enabled in `ConfigManager`, players without the `umbrellaos.maintenance.bypass` permission are kicked with a message from `MessageTemplateManager`. |
| `minecraft-plugin/src/test/java/com/umbrellaos/plugin/VerificationCommandTest.java` | 32 unit tests covering code validation, API response handling, `/umbrella` sub-commands, `/appeal`, and tab-completion. |

## Commit `031f8a2` — Feature flags permissions seed + Bot RemoteConfig foundation

### What changed

#### `umbrella-core-CURRENT/services/roles_service.py`

Added two new permissions to `DEFAULT_PERMISSIONS`:
```python
("feature_flags.view",   "View feature flags")
("feature_flags.manage", "Create, update, and delete feature flags")
```
These were previously only seeded directly into the live Supabase DB, meaning a fresh deploy or DB wipe would silently lose them. Now they're in code and will always be seeded on startup.

Roles updated:
- `owner` → gets both `feature_flags.view` and `feature_flags.manage` (via `ALL_PERMISSION_KEYS`)
- `admin` → gets both (via `ALL_PERMISSION_KEYS`)
- `moderator` → gets `feature_flags.view` only

#### `umbrella-core-CURRENT/services/settings_service.py`

Added 7 `discord.*` keys to `DEFAULT_SETTINGS` so the bot can fetch them from core's settings API instead of reading them from `.env`:

| Key | Value |
|---|---|
| `discord.guild_id` | `1503072397828423700` |
| `discord.staff_alert_channel_id` | `1503076452994650323` |
| `discord.verified_role_id` | `1540853515201544282` |
| `discord.owner_role_id` | `1503074796702011582` |
| `discord.callback_url` | `http://free-bots.heavencloud.in:3607` |
| `discord.callback_port` | `3607` |
| `discord.command_prefix` | `!` |

#### `umbrella-discord-CURRENT/bot/config.py`

Added a `RemoteConfig` dataclass to hold the values fetched from core:
```python
@dataclass
class RemoteConfig:
    guild_id: int
    staff_alert_channel_id: int
    verified_role_id: int
    owner_role_id: int
    callback_url: str
    callback_port: int
    command_prefix: str
```
Also added `fetch_bot_config(core_client)` which reads all 7 keys from `/api/v1/settings/{key}` and returns a populated `RemoteConfig`, falling back to hardcoded defaults if any key is missing so the bot always starts cleanly.

#### `umbrella-discord-CURRENT/bot/bot.py`

In `setup_hook`, after the core client is initialised, the bot now calls `fetch_bot_config(self.core)` and stores the result as `self.remote`. This is the foundation for removing the remaining old env vars — cogs can now read e.g. `self.bot.remote.staff_alert_channel_id` instead of `os.getenv(...)`.

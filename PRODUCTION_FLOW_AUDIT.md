## Prioritized unresolved production fixes

1. **High — Server-scoped plugin authorization and command idempotency.** Introduce distinct credentials/identity per Minecraft server, authorize poll + acknowledge against that identity, and a command claim/lease + idempotent completion protocol. The current shared-key server_id filter is not an authorization boundary; in-memory dedup alone cannot provide crash-safe exactly-once execution.
2. **High — Versioned, request-bound bot MAC.** Sign HTTP method, path, timestamp, nonce, and body hash; reject nonce replays; coordinate Discord bot→Core and Core→bot migration. The existing timestamp-only PBKDF2 MAC remains replayable inside its acceptance window.
3. **High — Durable Discord broadcast delivery.** Persist a delivery/outbox record and status, retry failures with idempotency keys, and make the dashboard distinguish *accepted*, *queued* and *delivered*. Current best-effort push loses one-shot broadcasts during bot outages.
4. **High — Network egress hardening.** Registration/delivery now reject direct private destinations but DNS validation before an HTTP request does not fully prevent DNS-rebinding/time-of-check-to-time-of-use attacks. Pin the actual connected address or enforce egress-network controls; review all third-party webhook paths.
5. **Medium — Public chat AI usage limits.** The new restricted plugin endpoint intentionally has no privileged tools, but should acquire explicit per-server cost/rate budgets before broad enablement. Also give public AI responses a safety review appropriate to in-game chat.
6. **Medium — Remote server control contract.** Distinguish Core-local process commands from remote node operations and wire the latter through an authenticated daemon/agent, rather than treating a `server_id` label as a remote execution target.
7. **Medium — Console delivery idempotency.** Failed HTTP calls now retain logs, but a successful DB write followed by a lost response can resend the batch. Add per-line/batch sequence IDs and deduplication if exact-once persistence is needed.
8. **Medium — Sandbox isolation.** `services/plugins/sandbox.py` restricts Python builtins and uses OS limits, but its own code documents that it is not a kernel/container security boundary. Consider a dedicated restricted worker/container and review fork-in-thread behavior.
